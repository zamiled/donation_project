# Pulse — Streamer Donation Demo

เว็บรับโดเนทส่วนตัวสำหรับสตรีมเมอร์หนึ่งคน ใช้ React + Vite และ Go REST API จำลองการส่งเงิน ไม่มีการรับเงินจริง

## เริ่มต้น

Go 1.24+ และ Node.js 20.19+ หรือ 22.12+ (แนะนำ Node 24)

```sh
cd backend
go run .
```

เปิด terminal อีกหน้าหนึ่ง:

```sh
cd frontend
npm ci
npm run dev
```

ใน cloud นี้เพิ่ม `/workspace/tools/go/bin` ใน PATH เพื่อใช้ Go ที่ติดตั้งไว้
Frontend พอร์ต 5173; Go พอร์ต 8080; Vite proxy ส่ง `/api` ไป backend

## หน้าเว็บ

- `/` หน้าโปรไฟล์สตรีมเมอร์ ฟอร์มจำนวนเงิน ชื่อ และข้อความ → QR ทดลองล็อกยอด → อัปโหลดสลิป → รอตรวจสอบ
- `/dashboard` ดูยอดที่ยืนยันแล้ว เป้าหมาย และประวัติล่าสุด ตรวจสลิปแล้วกดยืนยันหรือไม่ผ่าน อัปเดตทุก 3 วินาที
- `/overlay` หน้าพื้นหลังโปร่งใสสำหรับ OBS Browser Source ขนาด 800 × 400

เปิด overlay ก่อนส่งโดเนท เฉพาะรายการที่เจ้าของสตรีมกดยืนยันแล้วจะแสดงตามลำดับครั้งละ 7 วินาที โดยตรวจรายการทุก 1 วินาทีและเริ่มแสดงภายในประมาณ 8 วินาที รายการเก่าตอนเปิดหน้าจะไม่ถูกเล่นซ้ำ การดึงข้อมูลจำกัด 20 รายการล่าสุด จึงเหมาะสำหรับ demo ที่มีรายการไม่ถี่มาก ยังไม่ได้ทดสอบในโปรแกรม OBS จริง

โปรไฟล์ตัวอย่างชื่อ `YOUR STREAM` และเป้าหมายอัปเกรดไมค์ 10,000 บาท อยู่ใน `/api/profile` ของ `backend/profile_handler.go` สามารถแก้ให้เป็นข้อมูลของคุณได้

รายการบันทึกใน `backend/data/streamer-donations.json` ซึ่งถูก ignore จาก Git แยกจากข้อมูลตัวอย่างโครงการเดิม ค่า `ADDR` เปลี่ยนที่อยู่ backend และ `DONATION_DATA_FILE` เปลี่ยนตำแหน่งข้อมูลได้

## API

| Method | Path | ผลลัพธ์ |
| --- | --- | --- |
| GET | `/api/health` | สถานะและโหมด demo |
| GET | `/api/profile` | โปรไฟล์ เป้าหมาย ยอด และจำนวนรายการ |
| GET | `/api/donations` | 20 รายการล่าสุด เรียงใหม่ก่อน |
| POST | `/api/donations` | สร้างรายการด้วย `amount`, `name`, `anonymous`, `message` |

ยอดจำนวนเต็ม 1–1,000,000 บาท ชื่อไม่เกิน 80 และข้อความไม่เกิน 300 ตัวอักษร ชื่อและข้อความเป็นข้อมูลสาธารณะใน demo ไม่ควรกรอกข้อมูลส่วนตัวจริง

## ขอบเขต

ยังไม่มี login, ระบบชำระเงินจริง, TTS, moderation หรือฐานข้อมูล production แดชบอร์ดเข้าถึงได้โดยไม่ต้องยืนยันตัวตน ใช้ทดลองในเครื่องก่อน ระบบ JSON รองรับ backend หนึ่ง process ฟอนต์ใช้ Google Fonts พร้อม sans-serif fallback

## Flow QR และสลิป (ทดลอง)

1. กรอกยอด ชื่อ และข้อความ แล้วกดแสดง QR ระบบสร้างรายการ `awaiting_slip` พร้อมรหัสและยอดที่เปลี่ยนไม่ได้
2. QR บรรจุรหัสรายการและยอด เป็น QR ทดลอง ไม่ใช่ PromptPay และจ่ายเงินจริงไม่ได้
3. เลือกภาพ PNG/JPEG ไม่เกิน 5 MB แล้วส่งหลักฐาน ภาพต้องตรวจอ่านได้และไม่เกิน 25 ล้านพิกเซล สถานะเปลี่ยนเป็น `pending_review`
4. เปิดแดชบอร์ด ดูสลิป แล้วกดยืนยันหลักฐาน (ทดลอง) หรือไม่ผ่าน สถานะเป็น `demo_confirmed` หรือ `rejected`
5. เฉพาะยอดที่ยืนยันแล้วจึงรวมในเป้าหมายและแจ้งเตือน overlay การอัปโหลดสำเร็จไม่ใช่การตรวจว่าจ่ายเงินจริง

API เพิ่มเติม:
- POST `/api/donations` คืน `{donation, uploadToken, qrPayload}`
- POST `/api/donations/{id}/slip` รับ multipart field `slip` พร้อม header `X-Upload-Token` จากการสร้างรายการ
- GET `/api/donations/{id}/slip` ดูหลักฐานใน demo
- POST `/api/donations/{id}/review` รับ `{ "decision": "approve" }` หรือ `reject`
- GET `/api/donations?confirmed=1` คืนเฉพาะรายการยืนยันสำหรับ overlay

ไฟล์ภาพอยู่ใน `backend/data/slips/` (ignored) โหมดทดลองนี้ยังไม่มีสิทธิ์แอดมิน: ผู้ที่เข้าแดชบอร์ดได้สามารถดูหลักฐานและตรวจรายการได้ ใช้ภาพทดลองที่ไม่มีข้อมูลส่วนตัวเท่านั้น ก่อนใช้จริงต้องเพิ่ม authentication/authorization และการตรวจยอด ผู้รับ สลิปซ้ำกับแหล่งข้อมูลธนาคารหรือบริการตรวจสลิป

หากกลับไปแก้ยอด ระบบจะสร้างรายการใหม่ รายการเก่าคงสถานะรอแนบสลิปไว้ ไม่มีผลกับยอดรวม หากรีเฟรชระหว่างส่งหลักฐานต้องเริ่มรายการใหม่ ยังไม่มีการกู้รายการค้างในหน้าเว็บ

## โครงสร้างไฟล์สำหรับแก้ไขโค้ด

Frontend แยกชื่อไฟล์ตามหน้าจอ ส่วน backend แยกตาม API/หน้าที่ โดยยังใช้ URL และ flow เดิม

```text
frontend/src/
├── main.jsx                       # เริ่ม React และเลือกหน้า overlay
├── App.jsx                        # layout, state ร่วม, สลับหน้า และเรียก API
├── pages/
│   ├── DonationPage.jsx            # หน้าผู้ชม: ฟอร์มโดเนทและเป้าหมาย
│   ├── DashboardPage.jsx           # หน้าสตรีมเมอร์: สถิติและตรวจสลิป
│   └── OverlayPage.jsx             # หน้าสำหรับ OBS: คิวแจ้งเตือน
├── components/
│   ├── DonationHistory.jsx         # ประวัติที่ใช้ร่วมกันสองหน้า
│   ├── PaymentModal.jsx            # หน้าต่าง QR และอัปโหลดสลิป
│   └── SubmissionReceipt.jsx       # ผลส่งหลักฐานสำเร็จ/รอตรวจ
├── lib/
│   ├── api.js                      # helper เรียก Go API ผ่าน Vite proxy
│   └── format.js                   # จัดรูปแบบจำนวนเงิน
└── style.css                      # CSS ร่วมของทุกหน้า

backend/
├── main.go                        # configuration และเริ่ม HTTP server
├── models.go                      # โครงสร้าง Donation และ Store
├── store.go                       # โหลด/บันทึกข้อมูล JSON
├── response.go                    # helper ตอบ JSON
├── routes.go                      # ลงทะเบียน URL ของ API ทุกเส้นทาง
├── health_handler.go              # สถานะ backend
├── profile_handler.go             # โปรไฟล์ เป้าหมาย และยอดรวม
├── donation_handler.go            # สร้างรายการและอ่านประวัติ
├── slip_handler.go                # อัปโหลดและเปิดภาพหลักฐาน
├── review_handler.go              # ยืนยันหรือปฏิเสธหลักฐาน
├── donation_handler_test.go        # ทดสอบข้อมูลรายการและการส่งพร้อมกัน
└── slip_review_test.go             # ทดสอบ QR/สลิปและสถานะการตรวจ
```

ทุกไฟล์ Go ยังอยู่ใน package เดียวกัน ใช้ `go run .` จากโฟลเดอร์ backend เพื่อรวมทุกไฟล์ ไม่ใช้ `go run main.go` ซึ่งจะไม่รวมไฟล์ที่แยกออกไป การติดตั้งและคำสั่ง frontend ยังเหมือนเดิม

ชื่อผู้ชมต้องไม่ว่างหรือเป็นช่องว่างล้วน ยกเว้นเลือก checkbox ไม่ประสงค์ออกนาม ซึ่งส่ง `anonymous: true` และไม่ส่งชื่อที่กรอกไว้ ระบบเก็บและแสดงเป็น “ผู้บริจาคไม่ประสงค์ออกนาม” ทั้งในประวัติและ overlay ถ้าเรียก API โดยตรงให้ส่งชื่อ หรือส่ง `anonymous: true` อย่างชัดเจน

## ภาษาไทย / English

เลือก TH หรือ EN ที่มุมขวาบน ระบบเริ่มด้วยภาษาไทยและจำภาษาที่เลือกใน localStorage (`pulse-language`) ข้อมูลฟอร์มและภาพสลิปที่เลือกไม่หายเมื่อสลับภาษา มีตัวเลือกภาษาในหน้าต่าง QR และผลส่งหลักฐานด้วย

ข้อความ UI, สถานะ, ข้อผิดพลาดของ API ที่ระบบรู้จัก, โปรไฟล์ตัวอย่าง และชื่อ anonymous แสดงตามภาษาที่เลือก ชื่อและข้อความจากผู้ชมไม่ถูกแปลอัตโนมัติ วันที่แสดงรูปแบบตามภาษา โดยยังใช้เขตเวลา Asia/Bangkok

ไฟล์ที่เกี่ยวข้อง:
- `frontend/src/i18n/messages.js`: ข้อความไทย/อังกฤษ ใช้ key เดียวกันทั้งสองภาษา
- `frontend/src/i18n/LanguageProvider.jsx`: state ภาษา, การจำค่า, helper `t`, รูปแบบเวลา/จำนวนเงิน และการซิงก์ระหว่างแท็บ
- `frontend/src/components/LanguageSwitcher.jsx`: ปุ่ม TH/EN

Overlay ไม่มีแถบเมนูเพื่อไม่ให้ติดบนสตรีม ใช้ภาษาที่บันทึกไว้และอัปเดตเมื่อเปลี่ยนภาษาในแท็บอีกหน้าของ browser เดียวกัน OBS มี browser storage แยกจาก browser ปกติ จึงอาจไม่ได้รับค่าที่เลือกใน browser นั้น
